# 未来教室 熊取校 生徒アンケート管理

目的：Googleフォームで集めた生徒アンケートを、Googleスプレッドシート経由で集計・可視化し、**生徒本人が感じている状態を塾長が短時間で把握する**ためのWebアプリを実装する。

注意：回答の入力はこのアプリでは行いません。講師向けの公開、ログイン、AI分析もMVPの対象外です。使う人は開発者と塾長だけです。

## 完成の定義（MVP）

デモデータ（2026年8月・9月）で、次ができればMVP完成とします。

1. 教室全体の主要指標を見る
2. 要確認の生徒と、その理由を見る
3. 生徒ごとの主要指標を比較する
4. 詳細画面で、今の状態・前月差・全34問を見る

実データをソースコードに書かない。認証情報をGitに入れない。未回答は0点にしない。

## 画面

ページは2つです。

- **状況確認（1枚）**: 左・中央・右の3列
- **生徒詳細**: 状況確認から生徒名をクリックして開く

### 状況確認

ヘッダーに校名、実施月（プルダウン）、その月の回答人数を置く。


| 列         | 目的          | 出すもの                                      |
| --------- | ----------- | ----------------------------------------- |
| 左：校舎の主要指標 | 今月の教室の状態    | 領域ごとの主要指標の平均。尺度は `/ 5`。領域平均は出さない           |
| 中央：要確認    | 気になる生徒を見つける | 生徒名と、領域ごとの要確認項目。1領域につき3件まで。超える分は件数だけ出し、押すとその場で残りを出す |
| 右：各生徒の回答  | 生徒を比較する     | 生徒名と主要指標。領域平均は出さない                        |


回答人数はヘッダー（実施月の右）に1つ出す。左列の各項目に同じ「回答 n人」は並べない。ある項目だけ未回答で分母が違うときのみ、その項目に「回答 9 / 10人」と出す。

左列の主要指標は次で固定する。

- 塾: 授業満足度、来月も頑張れそう
- 家庭学習: 計画達成、継続できそう
- 学校: 授業理解、テスト自信度
- 勉強: 楽しさ、モチベーション

右列も同じ主要指標だけを出す。塾・家庭学習・学校・勉強の質問を平均して1つの数字にはしない。目的変数・説明変数・アラート用途が混ざるため。

中央の表現は「要確認」「注意」「状態変化あり」までに止める。「退塾する」とは書かない。判定ルールは仮であり、後から変えられるように画面の外に置く。

### 生徒詳細

状況確認の生徒名から開く。ヘッダーに生徒名、学年、月のプルダウン、状況確認へ戻るリンクを置く。画面に「判定は仮ルールです。断定ではありません。」と出す。

閉じた状態は、塾・家庭学習・学校・勉強の4ブロックが、スマホでもPCでもスクロールなしで収まる。ブロックを開くと、その領域の5段階設問がすべて棒でその下に出る。開いたあとはスクロールする。画面遷移はしない。

各ブロックの左は、その領域の主要指標。棒と `/ 5`。前月の回答がある項目だけ `+1` `-2` を付ける。右は、その領域の5段階設問のうち仮ルールに当たったもの。印は「2以下」「注意」「先月-2」「未回答」。閉じた状態に入りきらない理由は、開いたときに出す。

5段階の設問はすべて仮ルールの対象にし、領域の中では日本語の表示名を出す。自主勉強時間、今の悩み、来月取り組みたいことは対象外で、勉強ブロックを開いたときに文言で出す。未回答は `—` とし、0にはしない。



## データ

正本はGoogleフォーム → Googleスプレッドシート。アプリはそれを読むだけです。開発中は同じ列構造のデモデータを使います。

- 生徒の識別は `student_id`。名前は表示用
- 定量質問は **5段階（1 = まったくそう思わない、5 = とてもそう思う）**
- 空欄・未回答・不正値は `null`。平均に0として入れない
- `study_daily_mitutes`（自主勉強時間）、`study_concerns`、`study_next_month_contents` は5段階ではない

列名は共有テストデータに合わせる。アプリ側で独自の型に作り直さない。

### 評価尺度について

MVPは5段階で扱う。画面では `4 / 5` のように出し、必要なら棒で高低を見せる。

過去の7段階回答と、いまの5段階回答を混ぜて前月比較しない。

将来、0〜100%の11段階などへ変える可能性はある。その場合はGoogleフォーム側の変更が先で、過去の5段階回答と混ぜて前月比較はしない。検討事項であり、MVPの5段階は変えない。

## やらないこと

- Webアプリからのアンケート回答
- 生徒向けログイン、講師向け権限管理
- AI分析、退塾予測、成績予測、自動通知
- 実生徒データのハードコード
- 装飾やアニメーションを目的にしたUI



## 技術

開発者が動作を追いやすいことを優先し、次で固定する。

- 画面: HTML / CSS / JavaScript
- サーバー: Node.js + Express（Google認証や集計をブラウザに出さない）
- 開発データ: `data/demo/` のデモJSON / CSV / xlsx

React や TypeScript はMVPでは使わない。ライブラリは必要最小限にする。

## リポジトリ運用

- 普段の作業は `develop`
- 機能追加は `feature/...` から Pull Request
- `main` は確定版。直接 push しない
- `.env` と実データはコミットしない
